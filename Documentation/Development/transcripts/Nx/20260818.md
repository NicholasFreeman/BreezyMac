⏺ Done — your diagnostic instinct was right. Here are direct answers.

  Were we reading one sensor, and was it the die temp?

  One sensor, and not reliably the hot spot. The old code walked a fallback list
  (TC0P, …, Tp09, Tp0T, …) and locked onto the first key that returned a 
  plausible value, then read only that one forever. On your Apple-Silicon Mac
  the Intel keys don't exist, so it landed on a single CPU-cluster sensor like
  Tp09 — and a single GPU sensor for the GPU. Neither is guaranteed to be the
  hottest core. So when your GPU test heated a different part of the die, our
  reading stayed "in range" while the machine actually throttled.
  AutomaticController already takes max(cpu, gpu), but that's the max of two
  cool readings — garbage in, garbage out.

  The fix

  BreezyMac now enumerates the whole SMC once (#KEY + read-by-index) and
  collects every Apple-Silicon die sensor — Tp/Te for CPU cores, Tg for the GPU
  — then reads the maximum across each group every tick. So both Automatic and
  Adaptive now track the actual hottest core / hottest GPU sensor, i.e. the
  throttle-relevant hot spot. (Intel Macs fall back to the old curated lists.)
  It's the standard "hottest core" approach fan-control tools use on Apple
  Silicon.

  I also, per your notes:
  - Dropped linear entirely — curves are always the smooth monotone-cubic spline
  now. The Smoothing picker and the dashed comparison overlay are gone.
  - Enabled the GPU curve by default (both power sources). This matters for your
  GPU test specifically: in Adaptive the GPU curve was previously off, so
  Adaptive ignored GPU heat completely. Now the max across CPU+GPU curves wins
  out of the box.
  - Kept your popover centering and the "Power source" label.

  I can't see your hardware, so I left a breadcrumb: on first sensor read the
